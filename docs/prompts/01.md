# 本文档项目通用的杂项提示词

## 039 <!-- 已完成 Codex正在做 --> 新建一个 vue 组件实现文件读取，修改，和文件导出

我的核心需求是这样的：

1. 我经常获取 sub2api 格式的 JSON 文件。
2. 我经常需要改动这些格式的文件，修改里面的 JSON 数据，然后生成满足我规格的文件。

我平时使用 `docs\ruan-cat-notes\docs\sundry\ai\sub2api\scripts\rewrite-wishtoapp-sub2api-name.ts` 就能手动完成文件修改需求了，但是效率不够高，需要更加好的交互方式，我现在的使用习惯是这样的：

1. 手动获取 sub2api 账号信息文件。
2. 手动复制文件到 `docs\ruan-cat-notes\docs\sundry\ai\sub2api\has-used-sub2api-json` 目录内。
3. 手动改名，改成含有日期的格式。
4. 手动去 rewrite-wishtoapp-sub2api-name.ts 文件内更改 `TARGET_FILE_NAME` `ACCOUNT_BATCH_PREFIX` `notes` 这些变量。你可以用 git 看历史修改信息，rewrite-wishtoapp-sub2api-name.ts 文件近期的修改全部都是这 3 个变量的修改。
5. 手动执行 rewrite-wishtoapp-sub2api-name.ts typescript 脚本，完成文件修改覆写流程。

这个流程是很低效的，我不能接受了。我需要你做一个 vue 组件，实现更高的 UI 交互的效果，提高我的文件处理效率，而不是我再亲自去修改 typescript 脚本代码了。这很低效了。

你应该设计一个 UI 表单，重点实现对 ACCOUNT_BATCH_PREFIX 和 notes 字段的批量修改。

1. ACCOUNT_BATCH_PREFIX 设计一个输入框实现文本输入。
2. notes 设计一个长文本框实现可换行文本的输入。最终的文本应该包括 `\n` 这样的换行符。
3. 你应该大胆的使用 element-plus 组件库来实现这样的 vue 组件，我们的 `docs\ruan-cat-notes\docs` 本身就有很多基于 element-plus 表单的组件了。你应该去模仿学习怎么使用。

### 在 vitepress 内生成能直接使用的 vue 组件

在 `docs\ruan-cat-notes\docs` 目录内，我有专门设计一些 vue 组件，他们能直接在 vitepress 的 markdown 文档内渲染使用。你注意看清楚这些组件的定义方式，和在具体 markdown 文档内的使用规范，看清楚怎么在 vitepress 内的 markdown 文档内导入 vue 组件，并约束客户端渲染。

1. 你自己应该先安排一个子代理，去调研清楚到底怎么去组织清楚 vitepress markdown 使用客户端渲染的 vue 组件。
2. 然后你在 .agents\skills 内，模仿 `.claude\skills\write-juejin-posts\SKILL.md` ，编写一个项目级别的指导 skills，指导未来如何在 vitepress 的 markdown 文件内，定义、导入，并使用客户端渲染的 vue 组件。

### 文件读取和文件导出、不允许使用 node 来实现

这个需求要求你读取文件，然后实现文件生成。这个过程以往是需要 node 来参与的，但是你实际在生产环境内的使用场景是纯浏览器，纯 html。你就是一个 html 文件的 H5，所以你在编写 vue 组件逻辑时，对于目标 sub2api json 文件的读取、修改数据、和新文件生成，都不允许使用 node 来完成，因为生产环境是浏览器 H5 页面。你没有 node 环境。

### sub2api 的 JSON 文件数据格式

你应该安排子代理去看 `docs\ruan-cat-notes\docs\sundry\ai\sub2api\has-used-sub2api-json` 目录内包含日期命名格式的 JSON 文件，自己搞清楚 sub2api 的 json 文件数据格式。

### 本质上是对 `rewrite-wishtoapp-sub2api-name.ts` 函数的 UI 化、去 node 化、vue 化的改造任务

我的业务流程用 `rewrite-wishtoapp-sub2api-name.ts` 函数就能完成需求了，但是交互效果很累，所以需要你完成这样的任务。理解清楚任务本质。

你制作的这个组件在这个位置导入使用。

### 浏览器验证

尽量不要启动整个 notes 项目，这个 vitepress 体量太大了，你本地启动服务很慢，很卡，容易失败。你应该用别的低成本方案实现组件的测试。用 agents-browser 来完成浏览器验证，少使用谷歌浏览器 MCP。
